## 要解决的具体问题
面向维护 VS Code 扩展和键位包的开发者：修改 when 条件或平台键位后，确认“普通编辑仍保存、显式模式触发扩展、只读及非编辑焦点不误触发”等既定行为没有改变。
扩展可以覆盖默认绑定，这类问题在 VS Code 官方排障说明和历史需求记录中有公开依据；它们不是本项目已有用户的证明。
真实键盘受宿主和布局影响，因此本项目不再宣称面向所有编辑器的通用冲突解析器。

## 现有方案与独立价值
VS Code 已有 Show Same Keybindings、键盘排障日志和实机集成测试，应优先用于个人配置及真实键盘问题。
本项目补充的是“把相关配置快照和明确状态契约纳入发布前 CI”：不只报告重复键，还对比每个状态下预期命令与实际选中规则，并输出条件轨迹。
独立库的理由是复用同一份原生格式导入、限定条件解析、顺序判定和报告实现，而不是复制两套脚本。
目前已由 MoonBit/wasm 文件 CLI 和直接导入编译后 JS 的 Node 调用端共同使用；这不等于已有外部产品采用。
如果只维护少量个人快捷键，内置工具更合适，不主张为此引入本库。

## 已实现的场景与技术路线
读取扩展 package.json 的 contributes.keybindings、相关默认规则、用户覆盖和显式 context/expected_command 场景。
用纯 MoonBit 内核处理 key 与平台覆盖、布尔 when（!、&&、||、括号）、后置匹配优先、命令期望与解释轨迹。
原创开发扩展样例中，两份配置的按键相同，放宽 when 后三个指定状态回归；修复条件后五个状态通过。
样例含可加载的扩展贡献和命令处理器，反例是故障注入，不伪称线上事故或真实客户数据。
CLI 与 JS 的跨平台声明输入对照可运行 `node scripts/test_vscode.mjs`，具体步骤见 examples/vscode-review/README.md。

## 明确的功能边界
只验证给定快照和列出的状态；调用者须提供完整的相关规则顺序，不推断任意扩展安装环境。
未支持条件操作符、缺少必要状态、删除/禁用规则、args、systemWide、布局/扫描码和中断 chord 等返回 inconclusive，不判为安全。
不执行命令、不监听键盘、不改写配置；真实宿主键盘事件、命令可用性及第三方扩展顺序仍需实机核对。
